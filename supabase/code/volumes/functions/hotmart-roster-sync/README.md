# Hotmart roster sync

This Edge Function uses the official Hotmart application-auth flow and the
official subscriptions collection:

- OAuth token: `POST https://api-sec-vlc.hotmart.com/security/oauth/token`
- Roster source: `GET https://developers.hotmart.com/payments/api/v1/subscriptions`
- Official references: [application authentication](https://developers.hotmart.com/docs/en/start/app-auth)
  and [get subscriptions](https://developers.hotmart.com/docs/pt-BR/v1/subscription/get-subscribers/).

Configure these **Edge Function secrets**; never expose them in Expo or in the
admin web bundle:

- `HOTMART_CLIENT_ID`
- `HOTMART_CLIENT_SECRET`
- `HOTMART_BASIC_TOKEN` (the Basic credential generated by Hotmart)
- `HOTMART_PRODUCT_ID` (the Casa de Isabel subscription product)
- `HOTMART_ROSTER_STATUSES` (optional CSV; defaults to
  `ACTIVE,DELAYED,OVERDUE`)

The function requires an authenticated `admin` or `support` user. `POST` with
`{"action":"cohorts"}` previews cohort counts. `POST` with
`{"action":"sync"}` persists the roster and synchronizes every group whose
required `cohort_number` matches. `group_id` may be sent by the creation flow
or by “Sincronizar turma agora”; in that case only the selected cohort is
persisted and every group linked to that same cohort is reconciled atomically.
The global sync remains responsible for refreshing every cohort and every
group. A sync is a reconciliation: cancelled
students and students moved to another
cohort are deactivated and removed from the previous group; active students
remain preassigned by e-mail even before creating an app account.

For safety, a sync that returns no eligible students, fewer than 25% of a
previous roster with at least ten students, or unexpectedly empties/reduces an
individual cohort returns
`roster_confirmation_required` without removing any association. After
reviewing the product/status filters, an administrator may repeat the request
with `{"action":"sync","force":true}`. The admin panel only exposes this
second step after an explicit confirmation, so a legitimate mass cancellation
can be reconciled without silently preserving access forever.

Cohorts are derived only from Hotmart `plan.name` values containing the `T19`
pattern already used by `hotmart-auth/cohort.ts`. No credential, endpoint, or
student is fabricated when a plan does not contain a cohort code.
